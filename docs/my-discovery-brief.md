### Docker explanation for class

Git repository/source code → Docker image → running container → Next.js development server → localhost:3000 → browser.

- The repository holds the source and configuration. The Dockerfile builds an image with Node.js 24 and the project's dependencies. An image is the packaged environment; a container is a running instance of it.
- Docker Compose reads `compose.yaml` and manages this project's `web` service, build target, mounts, port mapping, and health check. Its startup command runs `npm ci` from the lockfile, then `npm run dev`.
- The source bind mount, `.:/app`, shares this WSL project folder with `/app` inside the container. Saving a source edit changes the files Next.js watches, so the development server can rebuild the affected page and update the browser without rebuilding the Docker image.
- Named volumes store Linux dependencies at `/app/node_modules` and generated Next.js caches at `/app/.next`. They remain after ordinary container removal and are separate from the source code. They are not backups.
- `127.0.0.1:${APP_PORT:-3000}:3000` maps localhost port 3000 by default to port 3000 inside the container. The browser uses the host port; Next.js serves the app inside the container. This is local access, not public website deployment.
- For this Windows setup, Docker Desktop and WSL2 provide the Linux environment. The running `web` service was observed healthy on localhost:3000 during this task.

See [Docker basics](docker-basics.md) and [development commands](development.md). These notes support my explanation in class; personal understanding still needs my confirmation.
